# QueueNova: design.md

Audience for this file: the frontend agent (Gemini 3.8 Flash in Antigravity). Read this file fully before writing any UI code. Read architecture.md for data and logic, techstack.md for tools.

## 0. Hard rules (paste these at the start of every frontend session)

1. No purple gradients. No gradients on any background, button, text or card.
2. No pill-shaped buttons. Buttons use a 6px corner radius.
3. No emoji anywhere (UI, copy, commit messages, alt text). Icons are SVG from lucide-react, imported by name.
4. No AI-generated images. Visuals are real UI components, SVG diagrams, or screenshots of this app.
5. No fake reviews, testimonials, customer logos, or invented user counts.
6. No fake metrics. Every number on screen comes from the app state. Anything seeded is labelled "Demo data".
7. No scroll-triggered animations. No parallax. No custom cursor or cursor effects.
8. No em dashes or en dashes in any file in the repo. Use a comma, a period, a colon, or the word "to".
9. No "Made with AI", "Built with AI", "Generated by" or similar tag in the footer, meta tags, comments or README.
10. No vague hero text. The hero must say what the product does, for whom, in plain words.
11. Banned words in copy: revolutionize, seamless, cutting-edge, next-generation, unlock, leverage, empower, supercharge, game-changing, effortless, elevate, transform your, harness, delve, tapestry.
12. Do not guess. If something here is unclear, ask instead of inventing.

## 1. Product naming

- Product name in the UI: **QueueNova**.
- The prototype has no trained model. Recommendations come from fixed rules. So the UI does not use the label "AI". Feature names:
  - SmartWait Pass
  - QueuePulse
  - AutoCounter (description: "Rule-based counter recommendations")
  - FairTurn
  - NovaNotify
  - NovaFlow (Predict, Prevent, Recover)
- The tagline "Less Waiting. Smarter Living." is vague. Do not use it. Use: **Digital tokens and live wait estimates.**

## 2. Visual language

### 2.1 Colour tokens (define as CSS variables in the Tailwind theme)

| Token | Hex | Use |
|---|---|---|
| --ink | #14202B | Body text, headings |
| --ink-muted | #4A5865 | Secondary text |
| --bg | #F7F8F6 | Page background |
| --surface | #FFFFFF | Cards, tables |
| --border | #D8DDD8 | Dividers, inputs |
| --primary | #0E5A63 | Primary buttons, links, focus ring |
| --primary-hover | #0A474F | Hover state |
| --on-primary | #FFFFFF | Text on primary |
| --calm | #1F7A4D | Calm status text and icon |
| --calm-bg | #E6F4EC | Calm status background |
| --busy | #8A4F00 | Busy status text and icon |
| --busy-bg | #FFF3DC | Busy status background |
| --critical | #B3261E | Critical status text and icon |
| --critical-bg | #FDE8E6 | Critical status background |

Rules:
- Flat colour only. No gradients, no glow, no heavy shadows. One subtle shadow is allowed on dropdowns: `0 1px 2px rgba(20,32,43,0.12)`.
- Status is never shown by colour alone. Always pair colour with an icon and the word (Calm, Busy, Critical).
- Verify every text and background pair with a contrast checker. Target at least 4.5:1 for body text and 3:1 for large text and UI borders. If a pair fails, darken the text colour, do not lighten the background.
- No dark mode in v1. Do not add a toggle.

### 2.2 Typography

- Fonts: IBM Plex Sans (400, 600) for text, IBM Plex Mono (500) for token numbers and times.
- Self-host via `@fontsource/ibm-plex-sans` and `@fontsource/ibm-plex-mono`. Import only the weights above, latin subset. Use `font-display: swap`.
- Scale (px): 14 small, 16 body, 18 lead, 24 h3, 32 h2, 44 h1 (desktop), 32 h1 (mobile).
- Line height: 1.5 body, 1.2 headings.
- Token numbers (for example QN-104) always use the mono font.

### 2.3 Shape, spacing, layout

- Spacing scale: 4, 8, 12, 16, 24, 32, 48, 64.
- Buttons: 6px radius, 44px minimum height, 16px horizontal padding. Primary is solid teal. Secondary is white with a 1px border. Danger is solid critical red and is used only for close counter and skip.
- Cards: 8px radius, 1px border, no shadow.
- Inputs: 6px radius, 44px height, visible label above the field (no placeholder-only labels).
- Container: max width 1120px, 16px side gutter on mobile, 24px on tablet and up.
- Breakpoints: 640, 1024.
- Focus: 2px solid primary outline with 2px offset on every interactive element. Never remove it.
- Touch targets: at least 44 by 44px.

### 2.4 Motion

Allowed:
- Colour and background transitions on hover and focus, 150ms.
- A 600ms background highlight on a number or row when its value changes (so staff notice a change). Disabled when `prefers-reduced-motion: reduce`.

Not allowed: scroll-triggered reveals, parallax, carousels, animated gradients, typewriter text, looping animations, page transition animations, custom cursors, particle effects.

### 2.5 Icons and imagery

- Icons: lucide-react, imported by name (`import { Clock } from "lucide-react"`). Never import the whole set. Icons that carry meaning have a text label or `aria-label`. Decorative icons use `aria-hidden="true"`.
- No stock photos, no AI images, no illustration packs.
- The landing page visual is a live component (section 4.1) built from the same state as the rest of the app.
- Open Graph image: a real screenshot of the Live queue page, 1200 by 630, taken from the finished app.

## 3. Site-wide requirements

### 3.1 Required pages

| Route | Page | Indexed |
|---|---|---|
| / | Landing | yes |
| /join | Customer portal, join a queue | yes |
| /pass | SmartWait Pass (reads `?t=QN-104`) | no |
| /live | Live queue dashboard | yes |
| /admin | Admin control centre (demo admin) | no |
| /admin/counters | Counter management and analytics | no |
| /terms | Terms and conditions | yes |
| /privacy | Privacy policy | yes |
| * | Custom 404 | no |

The pass uses a query string, not a path parameter, so it is one static page that the host can serve without rewrite rules.

### 3.2 Unique title, description and H1 per page

Every page has exactly one H1. No two pages share a title, description or H1. Titles are 60 characters or fewer. Descriptions are 120 to 155 characters.

Title pattern: `<Page title> | QueueNova`. The landing page is the one exception and uses the full string shown in the table.

| Route | Page title (full title for /) | H1 | Meta description |
|---|---|---|---|
| / | Full title: `QueueNova | Digital queue tokens with live wait estimates` | Know your wait before you join the line | QueueNova gives visitors a digital token and a live wait estimate, and shows staff which queues are filling up and which counters to open. |
| /join | Join a queue | Get your queue token | Choose a service, enter your name, and receive a digital token with an estimated wait and a suggested time to come back. |
| /pass | Your queue pass | Queue pass QN-104 (token number comes from the URL, so the H1 changes per token) | Track your token, estimated wait and notifications in one place. |
| /live | Live queue status | Live queue status | See who is being served, how many people are waiting, and how busy each queue is right now. |
| /admin | Admin control centre | Admin control centre | Call, complete, skip and recall tokens, and manage counters. Demo admin for the QueueNova prototype. |
| /admin/counters | Counters and analytics | Counters and analytics | Counter status, activity history, service durations and the Flow Score for the demo organisation. |
| /terms | Terms and conditions | Terms and conditions | The terms for using the QueueNova prototype, including limits on wait estimates and demo data. |
| /privacy | Privacy policy | Privacy policy | What QueueNova stores, where it is stored, and how to delete it. |
| * | Page not found | Page not found | The page you asked for does not exist. Go to the home page, join a queue, or view live queue status. |

Full titles to use in code: `QueueNova | Digital queue tokens with live wait estimates`, `Join a queue | QueueNova`, `Your queue pass | QueueNova`, `Live queue status | QueueNova`, `Admin control centre | QueueNova`, `Counters and analytics | QueueNova`, `Terms and conditions | QueueNova`, `Privacy policy | QueueNova`, `Page not found | QueueNova`. Landing title length is 57 characters. On /pass with no valid token the H1 is `Queue pass not found`.

Implement metadata with the `Head` component of the prerender tool (one per page component, values from one `seo.ts` map that mirrors this table) and prerender every static route at build time so crawlers receive the correct tags in the HTML. After a build, open `dist/<route>/index.html` for each page and confirm the title, description and H1. See techstack.md.

Also on every page: `<html lang="en">`, a canonical link to `https://YOUR-DOMAIN/<route>`, Open Graph and Twitter card tags, and a skip-to-content link.

Pages marked "no" in the Indexed column include `<meta name="robots" content="noindex, nofollow">`.

### 3.4 robots.txt and sitemap.xml

`public/robots.txt`:

```
User-agent: *
Allow: /

Sitemap: https://YOUR-DOMAIN/sitemap.xml
```

Why `/admin` and `/pass` are not disallowed here: a crawler that is blocked by robots.txt never reads the noindex tag, so the URL can still appear in results. These pages use `noindex` in the HTML instead, which is the reliable method.

`public/sitemap.xml` lists only the indexed routes: `/`, `/join`, `/live`, `/terms`, `/privacy`. Use the real domain. Generate it in the build script from the route list so it cannot drift.

### 3.5 Custom 404 page

- Route: any unknown path. Build output includes `404.html` at the site root (the static host serves it with a 404 status).
- H1: `Page not found`.
- Body: `The page you asked for does not exist or has moved.`
- Three links: Home, Join a queue, Live queue status.
- Same header and footer as other pages. `noindex`.
- Never auto-redirect to the home page.

## 4. Page specifications

All pages share a header (logo mark plus "QueueNova", links: Join a queue, Live queue status, Admin) and the footer above. The header has a "Demo data" badge (rectangular, 4px radius, border) on every page that shows seeded records.

### 4.1 Landing (/)

Sections, in order:

1. **Hero.** H1: `Know your wait before you join the line`. Supporting text: `QueueNova gives each visitor a digital token, a live estimate of their wait, and a time to come back. Staff see which queues are filling up and which counters to open.` Two buttons: `Join a queue` (primary, links to /join) and `Open admin demo` (secondary, links to /admin). Right side (stacked below on mobile): a live panel component that reads the same state as /live. It shows currently serving token, people waiting, and the QueuePulse status for one service, with the caption `Demo data. Resets when staff reset the demo.` No stock image.
2. **How it works (NovaFlow).** Three columns with plain text:
   - Predict: `Each token shows people ahead, estimated wait and a return window, recalculated whenever the queue changes.`
   - Prevent: `QueuePulse flags a queue as Calm, Busy or Critical. AutoCounter suggests opening a counter and says why.`
   - Recover: `If a counter closes or a visitor misses their turn, estimates update and affected visitors are notified in the app.`
3. **What you get.** Four feature blocks (SmartWait Pass, QueuePulse, AutoCounter, FairTurn), each with a one-sentence description and an SVG icon. NovaNotify is covered inside SmartWait Pass.
4. **Limits, stated plainly.** A short box: `This is a prototype. Data is sample data stored in your browser. Notifications appear inside the app only. Wait times are estimates.`
5. Footer.

Do not add: testimonials, partner logos, "trusted by" rows, counters like "10,000 users", pricing, newsletter forms.

### 4.2 Join a queue (/join)

Form order: organisation, service, name, walk-in or appointment, appointment slot (only when appointment), priority request (optional, with the rules text next to it), submit button `Get my token`.
- Show the published ordering rules above the form: priority (after staff check), then valid appointments, then walk-ins, first come first served inside each group.
- Priority checkbox label: `I am requesting priority under the rules above. Staff will check this before it applies.`
- Validate before submit: name 1 to 60 characters, service required, slot required for appointments.
- Appointment outside its valid window: show `This slot is outside its window. You can join as a walk-in instead.` with a button.
- On success: go to `/pass?t=<token>`.
- Show an estimated wait for the chosen service before the user submits, or `Waiting for an available counter` when no compatible counter is open.

### 4.3 SmartWait Pass (/pass)

Shows, in this order: token (large, mono), service, status badge, people ahead, estimated wait, suggested return window, confidence label (Stable or Changing), currently serving token and counter, notifications list (newest first). If the token is not found, show an inline message with a link to /join, not a blank page.
- Estimated wait with no compatible counter: `Waiting for an available counter`.
- Return window text: `Come back in 15 to 17 minutes`. If the estimate is 5 minutes or less: `Stay nearby, your turn is close`.
- Button `Leave the queue` with a confirmation dialog.

### 4.4 Live queue (/live)

Customer names are never shown on this page, only token numbers. Top row: currently serving (per counter), people waiting, completed today, active counters. Then per service: QueuePulse badge with its reason sentence, estimated wait for a new arrival, and the AutoCounter recommendation with its reason. Then recent activity (last 10 events).

### 4.5 Admin control centre (/admin)

- Banner at the top: `Demo admin. No sign-in is enforced in this prototype.` (Phase 2 replaces it with a passcode form.)
- Per counter card: status, current token, buttons depending on state: `Call next`, `Start service`, `Complete`, `Mark missed`, `Open`, `Close`.
- Disabled buttons must show the reason as visible text (not only a tooltip). Example: `Cannot close while serving QN-104. Complete the service first.`
- Waiting list table: token, name, service, tier, joined time, estimated wait, `Approve priority` and `Reject priority` when pending, `Skip`.
- Missed list: token, missed time, grace time left, `Recall`, `Return to queue`.
- Recommendations panel and notifications panel.
- `Reset demo data` button with a confirmation dialog.

### 4.6 Counters and analytics (/admin/counters)

- Counter table: name, supported services, status, current token, `Edit services` (disabled while serving).
- Add counter form.
- Metrics: total registrations, completed services, average service duration, peak queue length, active counters, estimated versus actual duration (simple two-bar SVG), counter utilisation (per counter: serving minutes divided by minutes not closed, from stored records, see architecture.md section 9).
- Flow Score with the formula printed under it (see architecture.md section 9). Label it `Flow Score (QueueNova demo formula)`.
- Activity history table, newest first.

### 4.7 Terms, privacy, 404

As in sections 3.5 to 3.7. Long text pages use a 65 character reading width, h2 per numbered section, and a "Last updated" line.

## 5. Accessibility checklist

- One H1 per page, headings in order, landmarks (header, main, nav, footer).
- All form fields have visible labels and error text linked with `aria-describedby`.
- Status changes (new notification, ETA change) announced with `aria-live="polite"` on one region per page.
- Fully usable by keyboard. Dialogs trap focus and close on Escape.
- Respect `prefers-reduced-motion`.
- Colour contrast as in section 2.1.

## 6. Pre-commit design QA (run before every commit)

```
# 1. No dash characters or emoji or any non-ASCII in source and public files
grep -rnP "[^\x00-\x7F]" src public index.html README.md

# 2. No gradients or purple
grep -rniE "gradient|purple|violet|indigo" src public index.html

# 3. No pill buttons
grep -rniE "rounded-full|border-radius: *9999|rounded-\[999" src

# 4. No banned copy
grep -rniE "revolutioni|seamless|cutting-edge|next-generation|unlock|leverage|empower|supercharge|game-chang|effortless|elevate|harness|delve|tapestry" src public index.html

# 5. No AI tags or fake social proof
grep -rniE "made with ai|built with ai|generated by|powered by ai|testimonial|trusted by" src public index.html
```

Each command must print nothing. Exception: the privacy and terms files may need non-ASCII characters later (for example a currency symbol). If so, allow-list that exact character and file, never the em dash or en dash.
